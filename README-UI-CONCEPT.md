# Wiren Board — полный UI concept

Альтернативный полный фронтенд установленной версии Wiren Board: `v2.208.1-wb100`, upstream commit `0546d10e7ade2894baa5a828549900b708ca52a8`. Это fork настоящего приложения с сохранёнными страницами, редакторами, транспортом MQTT/RPC, авторизацией и правами. Интерфейс не встраивает прежний UI и не отправляет пользователя на порт 80 для настройки.

После установки интерфейс доступен на `http://<controller>:8080/#!/overview`. Используйте адрес своего контроллера и существующую учётную запись. Сессия разделяется между портами одного hostname; обычный выход завершает общую браузерную сессию WB.

## Что изменено

- Новая постоянная навигация, контекстная строка, зелёная палитра WB, более ясная типографика, отступы, таблицы, формы и диалоги во всех штатных разделах.
- Новый обзор с реальными температурой, питанием, временем работы, состоянием каналов, сетью и историей CPU/платы.
- Избранные каналы на основе штатного компонента Cell, настраиваемые локально в браузере.
- Поиск по именам устройств, MQTT ID и каналам, доступный из навигации и раздела устройств.
- Каталог и карточка устройства: группы каналов, настройки, история выбранного канала и диагностика в одном контексте. Администратор видит устройства из конфигурации портов ещё до получения каналов.
- Сопоставление MQTT ID с конфигурацией `wb-mqtt-serial` даёт прямой доступ к нужному модулю. Повторяющийся ID показан как конфликт; для системных/виртуальных устройств и других драйверов отдельная serial-конфигурация не предполагается.
- Поиск, фильтр, выбранное устройство, вкладка и канал истории хранятся в URL; черновик конфигурации сохраняется при переходах внутри раздела устройств.
- Редакторы обычных панелей и виджетов, SVG и привязок, правил и конфигурации работают внутри приложения на том же порту.
- Сохранены serial/Modbus, сеть, пользователи и роли, история, журналы, системное обслуживание, MQTT-каналы, DALI и установленные интеграции/динамическое меню.
- Настройка панели по умолчанию продолжает работать при открытии корня; новый обзор доступен отдельно в меню и по `/#!/overview`.
- Обзор и новые элементы поддерживают RU/EN. Сохранены переменные и существующие средства разработки тем.
- Исправлена совместимость старой SVG-панели без поля `swipe`: значения по умолчанию добавляются в памяти редактора. Неверный SVG-атрибут `width="auto"` нормализуется только при отображении. Исходная конфигурация и привязки не переписываются.
- История устройства учитывает разницу часов браузера и контроллера. Настройки блокируют редактирование при сохранении и потере связи, включая уже раскрытые выпадающие списки.

Подробное покрытие штатных функций: [deploy/CAPABILITIES.md](deploy/CAPABILITIES.md).

## Работа с устройством

Раздел `/#!/devices` заменяет общий список карточек каталогом и рабочим местом выбранного устройства. Поиск учитывает имя, MQTT ID, каналы и, для администратора, порт, адрес и шаблон. Есть фильтры ошибок и устройств на портах. Записываемые каналы показаны первыми, затем входы и измерения; счётчики и служебные параметры по умолчанию свёрнуты. Группы определяются по доступным типам, доступности записи и названиям каналов: отдельных метаданных групп backend не передаёт.

История ограничена каналами выбранного устройства, график открывается внутри карточки. Сравнение нескольких каналов и выгрузка доступны по ссылке в штатную общую историю. Диагностика показывает ошибки устройства и каналов, сведения о подключении и полученные версии firmware/bootloader; по кнопке загружает до 20 записей `wb-mqtt-serial.service` с буквальным вхождением MQTT ID либо последние записи без фильтра. Пустой результат журнала и retained MQTT не подтверждают исправность или физическую связь: времени последнего ответа устройства в метаданных нет.

Оператору доступны каналы, история и диагностика; сопоставление с конфигурацией, настройки и версии прошивки — администратору. Системные MQTT-устройства подчиняются существующей настройке видимости. При неоднозначном MQTT ID настройки не выбираются автоматически. Полное дерево портов, добавление и операции с firmware сохранены в `/#!/serial-config` по ссылке «Все порты и добавление».

Настройки используют штатные схемы и валидацию. Открытие вкладки не запускает чтение физических регистров; это отдельное действие с подтверждением. Значения сначала попадают в черновик. «Сохранить» записывает **всю конфигурацию `wb-mqtt-serial`**, в том числе изменения других устройств; отмена перезагружает конфигурацию и отбрасывает весь черновик. Автосохранения нет, обновление страницы черновик не восстанавливает. Перед записью выполняется повторная загрузка и сравнение с исходной конфигурацией; при чужих изменениях запись отменяется. Между проверкой и записью остаётся окно гонки: атомарный compare-and-swap backend не поддерживает.

## Сборка

```sh
cd frontend
cp .env.concept .env
npm ci
npm test -- --runInBand
npm run build
```

Сборка — `frontend/dist/`. На контроллере работают только статические файлы и nginx, Node.js/npm ему не нужны. Зафиксированная версия зависимостей находится в package-lock.json.

`DISABLE_HTTPS_CHECK=true` отключает автоматический переход этого дополнительного фронтенда с 8080 на штатный HTTPS-порт 443. Общие настройки HTTPS контроллера и его штатный интерфейс не изменяются.

## Установка и отключение

Смотрите [deploy/README.md](deploy/README.md). Статика размещается на разделе данных `/mnt/data/wb-ui/releases`, активная версия выбирается ссылкой `current`. Добавляется только сервер nginx для 8080, штатный UI остаётся на 80. Предыдущий release сохраняется; установщик откатывает файлы при ошибке проверки или reload nginx.

Backend и его auth/ACL переиспользуются через reverse proxy. Это позволяет не менять службы, прошивку и рабочие конфигурации WB. Поддержаны native uploads, резервные копии, диагностические файлы и SVG assets.

## Проверка

- `npm test -- --runInBand`: **141/141 тест в 11 suites**. Покрыты исходные сценарии, права/режимы, отменённые переходы, offline-команды через порталы, локальное избранное/язык, точные ID истории со слешами, шкалы единиц, нули/CSV, отмена устаревших ответов, черновик панели и общие виджеты, конфликт/отказ Save, сохранение исходника ошибки правила и активный период из URL.
- Production Webpack build: два исходных предупреждения о размере bundles; предупреждений о порядке CSS нет. `tsc --noEmit` сохраняет 31 исходную ошибку upstream.
- Live QA v0.2.0 на WB7, порт 8080: режимы «Мой дом»/«Настройка», русский/английский и локальное применение языка, точные параметры опроса канала, изменение черновика и полный состав изменений без Save; исходное значение возвращено.
- История: температура и напряжение получены с реального backend и разнесены по шкалам. CSV скачан при свёрнутой таблице; диапазон и выбранный быстрый период видны, ссылки восстанавливают каналы и даты.
- Текстовая панель: состав, расположение и предпросмотр с живыми значениями; тестовое изменение названия отменено через явный диалог. Предпросмотр не содержит переключателей/команд. Успешные записи, общие виджеты, сохранение при ошибках и конфликты проверяются на изолированных моделях, а не записью рабочих панелей WB.
- Правила: редактор существующего правила, живые сообщения и явная загрузка 20 реальных записей `wb-rules`. В изолированных проверках ошибка для отправленного B сохраняет исходник B при последующем редактировании C; переход по строке разрешён только при совпадении редактора с диагностическим снимком. Успешная запись при ошибочном ответе не предполагается.
- Новые экраны проверены на ширинах 1440, 544 и 390 px. На узком экране редактор правил сохраняет прокрутку к диагностике под кодом, а таблицы и график — собственную область просмотра. Публичный снимок «Мой дом» создан из реальных компонентов с синтетической конфигурацией; реальные приватные снимки проверки не публикуются.
- nginx, mosquitto, wb-mqtt-serial и wb-rules активны; порты 80 и 8080 отвечают HTTP 200. Контрольные суммы `/etc/wb-mqtt-serial.conf` и `/etc/wb-webui.conf` до и после live QA совпали. При проверке выходы не переключались, конфигурация не сохранялась, сканирование не запускалось; firmware, сеть и пользователи не изменялись.
- В предыдущей версии проверены штатные вход/session, live MQTT, обычные/SVG панели и редактор, журнал, страницы портов, пользователей, сети, MQTT, configs, widgets и Alice. Физическое DALI-оборудование и совместимость других backend не проверены. Результаты CI опубликованных ревизий — в [GitHub Actions](https://github.com/evstratbg/wb-ui/actions/workflows/ci.yml).

## Основные файлы

- `frontend/src/components/navigation/` — оболочка приложения.
- `frontend/app/styles/concept.css` — общие native компоненты и адаптация.
- `frontend/src/pages/overview/` — новый обзор и реальная история.
- `frontend/src/pages/devices/` — каталог, группы каналов, настройки, история и диагностика устройства.
- `frontend/app/scripts/react-directives/devices/` — MQTT/RPC и адаптер штатного редактора конфигурации.
- `frontend/src/stores/ui/menu-items.ts` — навигация и права.
- `frontend/src/pages/dashboards/svg/` и `frontend/src/utils/svg-for-display.ts` — совместимость SVG.
- `frontend/test/react/concept/` — регрессионные тесты.
- `deploy/` — установка, reverse proxy и откат.

Это независимое предложение интерфейса, не официальный релиз Wiren Board. Исходная MIT-лицензия и авторство сохранены в [LICENSE](LICENSE). Backend и пакетные конфигурации оставлены исходными; deploy использует существующий backend установки.
