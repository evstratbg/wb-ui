# wb-ui

**Экспериментальный интерфейс для Wiren Board.** Рабочее место инсталлятора: найти устройство, проверить каналы, открыть его настройки, историю и диагностику в одном контексте.

> Независимый концепт, не официальный продукт Wiren Board. Основан на полном приложении [wirenboard/homeui](https://github.com/wirenboard/homeui). Переработаны оболочка, обзор и работа с устройством; штатные редакторы и backend сохранены. Следующие сценарии описаны в [планах](ROADMAP.md).

## Что стало удобнее

| Задача | Раньше | Теперь |
| --- | --- | --- |
| Проверить и настроить модуль | Каналы, конфигурация портов, история и журнал в разных разделах | У выбранного устройства есть вкладки «Каналы», «Настройки», «История» и «Диагностика» |
| Найти настройки по каналу | После поиска канала нужно заново искать модуль в дереве портов | Точный MQTT ID связывает устройство с его конфигурацией и показывает порт и адрес |
| Найти нужный выход или показание | Управление и служебные каналы в общем списке | Сначала управление, затем входы и измерения; счётчики и служебные каналы свёрнуты |
| Посмотреть изменение значения | Переход в общую историю и выбор канала | История выбранного канала внутри устройства; ссылка на общую историю для сравнения и выгрузки |
| Разобраться с ошибкой | Сопоставление каналов, конфигурации и журнала вручную | Ошибки устройства и каналов, подключение, полученные версии firmware/bootloader и загрузка журнала драйвера рядом |
| Вернуться к найденному устройству | Поисковый контекст легко потерять при переходах | Поиск, фильтр, устройство, вкладка и канал истории в URL; ссылка на карточку и возврат к списку сохраняют контекст |
| Найти модуль без каналов | В списке MQTT ещё нечего показать | Администратор видит устройства из конфигурации портов и до получения MQTT-каналов |

Настройки открываются только при однозначном совпадении MQTT ID. При дубликатах показан конфликт; для системного, виртуального устройства или другого драйвера интерфейс сообщает об отсутствии отдельной конфигурации `wb-mqtt-serial`. Доступ к системным MQTT-устройствам по-прежнему зависит от штатной настройки их видимости.

Оператору доступны каналы, история и диагностика. Конфигурация портов, настройки и сведения о прошивке доступны администратору. Полное дерево портов, добавление устройств и штатные операции с прошивкой остаются в разделе «Все порты и добавление».

Правки настроек остаются в черновике при переходе между устройствами и вкладками. Автосохранения нет: «Сохранить» применяет **весь черновик `wb-mqtt-serial`**, включая изменения других устройств. Перед записью конфигурация повторно загружается; если она изменилась в другом окне, сохранение отменяется. Это проверка устаревших данных, а не атомарная блокировка: backend не предоставляет compare-and-swap. Обновление страницы не сохраняет черновик.

Статус «Ошибок не получено» не доказывает связь с физическим модулем: backend не передаёт время его последнего ответа. Журнал загружается по запросу: до 20 записей драйвера с буквальным вхождением MQTT ID или последние записи без фильтра; не все сообщения драйвера содержат ID.

## Что ещё изменено

- Постоянная навигация, контекстная строка, поиск устройства или канала с клавиатуры (`Ctrl/Cmd + K`).
- Обзор: температура, питание, время работы, сеть, ошибки каналов и история CPU/платы.
- Избранные каналы с локальной настройкой в браузере.
- Поиск по имени устройства, MQTT ID и названиям каналов.
- Общие стили форм, таблиц, диалогов и штатных редакторов; адаптация для телефона; RU/EN для новых элементов.

## Конкретные исправления

- Старая SVG-конфигурация без `swipe` открывается с настройками по умолчанию в памяти редактора.
- SVG с `width="auto"` нормализуется только при отображении, без переписывания исходной панели и привязок.
- Оси графика остаются читаемыми на узком экране.
- Подписи поиска находятся в правильном namespace переводов устройств.
- Сохранённая MQTT-ошибка самого устройства участвует в статусе и диагностике, даже если отдельные каналы не сообщают ошибок.
- Диапазон истории устройства учитывает разницу часов браузера и контроллера, чтобы получать актуальные точки.
- Во время сохранения и при потере связи заблокировано редактирование настроек, включая уже раскрытые выпадающие списки.

Внутри приложения остаются устройства и Modbus-порты, конфиги, сеть, правила, пользователи и роли, история, журналы, обычные/SVG-панели с редакторами, MQTT и установленные интеграции. Используются существующие backend, авторизация и MQTT/RPC контроллера. [Карта возможностей и проверок](deploy/CAPABILITIES.md).

## Совместимость

| Компонент | Условия |
| --- | --- |
| Основа | homeui `v2.208.1-wb100`, коммит [`0546d10`](https://github.com/wirenboard/homeui/commit/0546d10e7ade2894baa5a828549900b708ca52a8) |
| Проверено | WB7 с backend этой версии; совместимость с другими версиями отдельно не подтверждена |
| Сборка | Node.js 22, npm; версия Node указана в [.nvmrc](.nvmrc) |
| На контроллере | Статические файлы, nginx и штатные службы WB; Node.js не нужен |
| Размещение | Дополнительный HTTP-порт `8080`, штатный интерфейс остаётся на `80` |

Приложение сохраняет существующий стек AngularJS + React 18 и Webpack. Это позволяет использовать штатные редакторы и установленные API без замены backend.

## Установка

Соберите на компьютере, затем загрузите статику на контроллер. В примере замените `wirenboard.local` на его имя или IP; нужен SSH-доступ `root`.

```sh
git clone https://github.com/evstratbg/wb-ui.git
cd wb-ui/frontend

# Если используете nvm: nvm use
cp .env.concept .env
npm ci
npm test -- --runInBand
npm run build

cd ..
WB_HOST=wirenboard.local
ssh "root@${WB_HOST}" 'mkdir -p /mnt/data/wb-ui-full-staging'
scp -r frontend/dist deploy/wb-ui.conf deploy/install-on-device.sh deploy/remove-on-device.sh \
  "root@${WB_HOST}:/mnt/data/wb-ui-full-staging/"
ssh "root@${WB_HOST}" \
  'sh /mnt/data/wb-ui-full-staging/install-on-device.sh /mnt/data/wb-ui-full-staging'
```

Откройте `http://<controller>:8080/#!/overview`. Вход — существующей учётной записью WB. Корневой маршрут `/#!/` продолжает открывать настроенную домашнюю панель.

Установщик размещает версии в `/mnt/data/wb-ui/releases`, переключает `current` и добавляет `/etc/nginx/conf.d/wb-ui.conf`. При ошибке проверки или reload nginx восстанавливает прежние файлы. Рабочие конфигурации и данные общие с основным интерфейсом: сохранённые изменения применяются к реальному контроллеру.

**[Полная инструкция: требования, обновление, откат, отключение и HTTPS](deploy/README.md).** Профиль `.env.concept` отключает автоматический переход этого фронтенда на порт 443; приложенный конфиг обслуживает HTTP на 8080 и не настраивает TLS для него. Настройки HTTPS контроллера не изменяются.

Чтобы отключить дополнительный UI:

```sh
WB_HOST=wirenboard.local
ssh "root@${WB_HOST}" 'sh /mnt/data/wb-ui-full-staging/remove-on-device.sh'
```

## Разработка и проверки

```sh
cd frontend
npm ci
cp .env.concept .env
npm test -- --runInBand
npm run build
```

Для разработки настройте `MQTT_BROKER_URI` и адрес backend в webpack-конфиге под свой контроллер, затем запустите `npm start`. Dev-сервер использует реальные службы контроллера; это не изолированный симулятор. Подробности исходного проекта — в [upstream README](docs/UPSTREAM.md).

Workflow CI настроен на тесты, production build и проверку синтаксиса deploy-скриптов. Артефакт `wb-ui-static` содержит сборку, установщик и лицензии; он не публикуется на контроллер автоматически. Результаты проверок каждой опубликованной ревизии доступны в [GitHub Actions](https://github.com/evstratbg/wb-ui/actions/workflows/ci.yml).

Локально пройдены **114/114 тестов в 9 suites** и production build с двумя исходными предупреждениями о размере bundles. У `tsc --noEmit` остаются ровно те же 31 ошибка upstream, что и до изменений. Новая сборка установлена на WB7 на порту 8080: проверены все четыре вкладки устройства, реальные точки истории и журнал, сохранение черновика при переходах, отмена выхода и явная отмена черновика. На ширинах 1440, 544 и 390 px горизонтального переполнения нет. Конфигурация на контроллере не сохранялась, физические выходы не переключались, сканирование не запускалось; firmware, сеть и пользователи не изменялись. [Подробный объём проверки](README-UI-CONCEPT.md#проверка).
